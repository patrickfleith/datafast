# Examples

Forty-five runnable scripts live in `examples/scripts/`. They are numbered so they build
up: the early ones use no LLM at all, the middle ones take one feature each, and the last
ones are whole datasets.

Every script runs on its own from the repository root and writes to `examples/outputs/`:

```bash
python examples/scripts/01_seed_product_basic.py
```

**Scripts 01–14 need no API key.** They build records, reshape them and write files, so
they are the cheapest way to see how a pipeline is put together. From 15 on, every script
calls a model through [OpenRouter](../reference/providers/openrouter.md) and needs
`OPENROUTER_API_KEY` in a `.env` file at the repository root — see
[Installation](../installation.md).

Most of the LLM scripts carry a commented-out `ollama(...)` line above the model they use.
Uncomment it, comment the other, and the script runs against a local model for free.

## Seeds and sources — no API key

Where records come from: built from dimensions, or loaded from somewhere.

| Script | What it shows |
|---|---|
| `01_seed_product_basic.py` | `Seed.values` and `Seed.product` — 3 topics × 2 difficulties × 2 languages = 12 records |
| `02_seed_zip.py` | `Seed.zip` pairs dimensions element-wise instead of crossing them |
| `03_seed_expand_and_range.py` | `Seed.expand` for parent–child pairs and `Seed.range` for numbers, crossed |
| `04_seed_with_sampling.py` | 192 combinations cut to 20 with `Sample`, uniform and stratified |
| `05_source_list_and_file.py` | `Source.list` and `Source.jsonl` in, JSONL and Parquet out |

## Data ops — no API key

The transforms that reshape records between the source and the sink. All of
[Data ops](../reference/data_ops.md), one script at a time.

| Script | What it shows |
|---|---|
| `06_map_transform.py` | `Map`: one record in, one record out |
| `07_flatmap_explode.py` | `FlatMap`: one record into many, exploding a list column |
| `08_filter_declarative.py` | `Filter` with `where` operators — `$gte`, `$in`, `$contains`, `$len_gt`, `$or`, `$and` |
| `09_filter_fn_and_drop.py` | `Filter(fn=...)` for anything the operators cannot say, and `keep=False` to invert |
| `10_sample_strategies.py` | all nine `Sample` strategies side by side |
| `11_group_aggregate.py` | `Group` with `collect`, aggregate functions and `min_per_group` |
| `12_pair_records.py` | `Pair` with the random, sliding and sequential strategies |
| `13_concat_sources.py` | `Concat` stacks several pipelines into one stream |
| `14_join_datasets.py` | `Join` on a shared key, inner / left / right / outer |

## LLM steps

One `LLMStep` feature per script. Together they cover most of
[LLM step](../reference/llm_step.md).

| Script | What it shows |
|---|---|
| `15_llm_text_mode.py` | the default: the whole reply becomes one column |
| `16_llm_json_mode.py` | `parse_mode="json"` splits one reply into several columns |
| `17_llm_xml_mode.py` | `parse_mode="xml"` does the same with tags |
| `18_llm_multi_prompt.py` | a list of prompts — every record runs through each, and gets `_prompt_index` |
| `19_llm_multi_model.py` | a list of models — every record is generated by each, and gets `_model` |
| `20_llm_languages.py` | `language={"code": "Name"}` multiplies records per language and adds `_language` |
| `21_llm_num_outputs.py` | `num_outputs=3` asks for three separate generations per record |
| `22_llm_system_prompt.py` | `system_prompt` to fix the voice across every call in the step |
| `23_llm_forward_exclude.py` | `forward_columns` and `exclude_columns` shape what comes out |
| `24_llm_prompt_from_file.py` | a prompt kept in a `.txt` file instead of the pipeline |
| `25_llm_skip_if.py` | `skip_if` bypasses the call for records that do not need it |
| `26_llm_sample_in_config.py` | `Sample` inside a step: pick a prompt per record, or a model once |

## Specialized LLM steps

The steps that ask for one specific thing and parse it for you —
[Specialized LLM steps](../reference/llm_specialized.md). Each has an `fn` mode that needs
no model at all, and several scripts show both halves.

| Script | What it shows |
|---|---|
| `27_classify_llm.py` | `Classify` with labels, an explanation and a confidence |
| `28_classify_multilabel_and_fn.py` | multi-label classification, then the same thing with a plain function |
| `29_score_llm_and_fn.py` | `Score` with criteria, a rubric and an explanation — then function scoring |
| `30_compare_responses.py` | `Compare` judges two columns head to head |
| `31_rewrite_paraphrase.py` | `Rewrite` in paraphrase mode, several variations per record |
| `32_rewrite_modes.py` | the other `Rewrite` modes: simplify, formalize, audience, custom |
| `33_extract_structured.py` | `Extract` with custom fields, a predefined extractor, and a regex function |

## Cookbooks

The four with a walkthrough on this site. Read the page next to the script.

| Script | What it builds | Walkthrough |
|---|---|---|
| `42_pipeline_preference_with_scoring.py` | chosen/rejected answer pairs, scored and filtered | [Preference data with scoring](preference_with_scoring.md) |
| `43_cookbook_persona_generation.py` | personas inferred from real articles, then expanded | [Persona generation](persona_generation.md) |
| `44_cookbook_space_text_generation.py` | a multilingual technical text corpus from a seed grid | [Space engineering text generation](space_text_generation.md) |
| `45_cookbook_text_classification.py` | a labelled multilingual classification set | [Text classification](text_classification.md) |

These three are the ones that publish: `43`, `44` and `45` can push to the Hugging Face
Hub, which needs `pip install "datafast[hub]"` and a token. Script 43 reads a Hugging Face
dataset as its source, so it needs the same extra even without publishing. **Point
`HF_REPO_ID` at a repository you own before running any of them.**
